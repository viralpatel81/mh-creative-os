How agentcy works

Five small programs in a row. Each one takes a file in and writes a file out. The output of one is the input of the next. That's the whole architecture.

The kitchen analogy

Think of a restaurant kitchen. The menu writer picks the voice ("rustic farm-to-table"). The chef writes the menu using that voice. A focus group tastes the menu and predicts which dishes will sell. The line cook plates the dish and sends it out. The floor manager checks what actually sold and tells the focus group "you were wrong about the duck." That's the loop.

The five modules, in order

1

persona — picks the voice

Who is doing the talking? Bootstrap a character (e.g. "Ashton from the farm"), test their voice for consistency, export them.

in: a description  ·  out: voice_pack.v1.json
2

brand — writes the plan

Given the brand definition and a topic, write a campaign brief: what's the angle, what's the CTA, which platforms, what policy guardrails.

in: voice_pack.v1 + brand.md + a topic  ·  out: brief.v1.json
3

forecast — predicts the reaction

Simulate a crowd of fake audience members and see how they would react to the brief. Returns scenarios with confidence scores. This is the most novel module.

in: brief.v1 + supporting docs  ·  out: forecast.v1.json
4

studio — makes and ships the post

Render the actual image or video, draft copy, publish to Twitter/LinkedIn/Meta/Threads. TypeScript, not Python.

in: brief.v1 + brand assets  ·  out: run_result.v1.json
5

metrics — measures and calibrates

Take the realized engagement data, normalize it, then compare against the forecast to update priors. This closes the loop.

in: run_result.v1 + actual engagement  ·  out: performance.v1.json
The key idea: The boxes don't call each other's functions. They write JSON files to disk, validated against a schema. That's why you can re-run any stage independently, replay an old forecast with new data, or swap one module for a different implementation entirely. It's schema-first design — rare in AI repos.

How to judge quality

When you compare this to other "AI creative" repos you've seen, look at three things:

1. Are the boundaries typed? Here they are — five JSON Schemas in src/agentcy/protocols/schemas/. Most repos pass dicts around and the shape drifts. This one rejects an artifact if it doesn't match the schema. That's the difference between a prototype and a platform.

2. Is there a feedback loop? Here, yes — metrics calibrate reads both the forecast and the realized performance and updates priors. Most repos only generate. This one learns.

3. Is the audience model real? Here, yes — forecast is a 66-file graph-and-swarm simulation built on camel-ai/oasis with its own ontology generator. Most repos "ask GPT to roleplay an audience." This one builds a network of agents with memory and watches them interact.
