persona

Defines who is doing the talking. Bootstraps an AI character, tests its voice for consistency, exports it as a portable artifact other modules consume.

What it actually does

You give it a description. It uses an LLM to flesh that description out into a structured character — traits, voice patterns, dos and don'ts, example responses. You can then chat with it, evaluate it, optimize it, mix two personas together, or export it.

The key output is a voice_pack.v1.json file. That's the artifact every other module reads to know how to write.

Why this is a separate module: a brand can be voiced by many personas (founder, vet partner, customer-success). A persona can voice many brands. Decoupling them means you can A/B test voices without changing the brand, and reuse one voice across multiple clients.

The Ashton example (we did this in chat)

Input — what we typed

$ uv run agentcy persona create \ "Ashton from Shepherd Boy Farms — a family member at a small Indiana freeze-dried raw pet food farm in Greensburg, Indiana. Talks to dog owners like a neighbor at a farm stand: warm, plainspoken, proud of the craft, willing to pick up the phone. Knows ingredients, cuts, and the freeze-dry process by name. Never overclaims, never goes medical..." \ --name ashton

Output — what the LLM filled in for us

Traits

approachable authentic knowledgeable friendly proud

Tone & Style

tone: casual vocab: simple and conversational patterns: - "You know, back on the farm..." - "Let me tell you about our freeze-drying..." - "Our pups absolutely love this stuff"

Boundaries (don'ts)

- never medical claims about dog health - no corporate jargon - no exaggerated benefits - not overly formal/technical - stays on pet food & farm

Example response (auto-generated)

"Hey there! You can't go wrong with our freeze-dried beef; it's from our farm and packed with quality. Our customer stories highlight how much their dogs enjoy it. Want to give it a try?"

The exported artifact (voice_pack.v1.json)

This is what gets handed to the brand module. ~2.6KB of normalized JSON.

{ "artifact_type": "voice_pack.v1", "schema_version": "v1", "voice_pack_id": "ashton.voice.default.v1", "brand_id": "ashton.brand.core", "writer": { "repo": "cli-prsna", "module": "agentcy-vox" }, "name": "ashton", "summary": "Ashton is a relatable family member...", "voice": { "tone": ["casual"], "style": ["simple and conversational", ...], "audience": ["general audience"] }, "constraints": { "dos": ["stay consistent with the persona summary..."], "donts": ["never medical claims...", ...] }, "traits": ["approachable", "authentic", ...], "examples": [ {"label": ..., "text": ...}, ... ] }

What's in the folder

17 Python files in src/agentcy/persona/. The interesting ones:

FileWhat it does
cli.py15 commands: init, create, ls, show, edit, rm, mix, chat, ask, export, enrich, test, evals, optimize, learn, critique, drift
bootstrap.pyLLM calls that fill in a persona from a description, a real person (via Exa), or a job role
exporters.py9 export formats: prompt, eliza, v2, ollama, hub, voice-pack, voice_pack.v1, ...
drift.pyGiven a response and a persona, score how far the response drifted from the voice
optimize.pyGEPA — a prompt optimization loop that tunes the persona prompt against evals
evals/Structured eval cases + saved reports

The full CLI surface

persona init <name> # empty scaffold — manual editing persona create <description> # LLM-bootstrapped persona persona create --like "Marc Andreessen" # bootstrap from real person via Exa persona create --role "senior PM at fintech" persona ls # list all personas persona show <name> # show details persona edit <name> # open in $EDITOR persona mix <a> <b> # blend two personas persona chat <name> # interactive REPL persona ask <name> "question" # single-shot Q&A persona test <name> # run consistency evals persona evals <name> # inspect saved eval reports persona optimize <name> # GEPA prompt optimization persona learn <name> # analyze interactions, suggest improvements persona critique <name> # self-critique persona drift <name> "response" # did this response drift from voice? persona enrich <name> # pull current info via Exa persona export <name> --to voice_pack.v1

Why this module is well-designed

The schema lock. The exported voice_pack.v1 has 9 required fields and rejects extras. That means the brand module never has to guess what fields exist — it's a contract.

Storage location matters. Personas live in ~/.prsna/personas/ (global, reusable), but the artifact snapshot lives inside the brand folder. You can iterate the persona without breaking deterministic brand runs — they read the frozen snapshot.

Optimization is real. GEPA is an actual prompt optimization algorithm (Genetic-Pareto). The persona isn't just "a system prompt" — it's something you can measure and improve against eval cases.
