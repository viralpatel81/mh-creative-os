brand

Given a brand definition and a topic, write a structured campaign brief. This is the largest, most sprawling module — it owns brand identity, planning, production, publishing, monitoring, and an autonomous loop.

What it actually does

The core flow: read brands/<id>/brand.md (identity, audiences, pillars, voice), read voice_pack.v1.json (the persona), take a topic from the user, and produce a brief.v1.json that contains: an objective, a signal (what's the input), a strategy (angle + CTA + platforms), policy (safety rails), and creative direction.

Around that core, the module also includes everything for autonomous operation: signal monitoring, content production, publishing queue, brand drift monitoring, decision logging, policy engine, and a self-running loop with a learning metric.

Heads up: this module is large — 112 Python files, 17 sub-CLIs. There is real risk of internal sprawl. For example, src/agentcy/brand/persona/ exists alongside the top-level persona module. When auditing this repo for quality, brand is where you'll find both the strongest engineering and the most accumulated complexity.

The command

$ uv run agentcy brand plan run \ "freeze-dried vs kibble — go after raw-curious dog owners" \ --brand shepherdboyfarms \ --json

What comes out — brief.v1.json (the schema)

11 required fields, strict — extras rejected. This is the contract every downstream module reads.

{ "artifact_type": "brief.v1", "schema_version": "v1", "brief_id": "sbf.brief.2026-05-12.001", "brand_id": "shepherdboyfarms", "voice_pack_id": "ashton.voice.default.v1", "writer": { "repo": "brand-os", "module": "agentcy-compass" }, "objective": "Convert raw-curious dog owners away from kibble", "signal": { "source": "pillar:raw-vs-kibble", "summary": "Owners suspect kibble causes allergies + dull coats", "evidence": [ ... ] }, "strategy": { "angle": "96% nutrient retention vs kibble's processing loss", "cta": "Subscribe with GOAT15 for 15% off first order", "platforms": ["instagram", "tiktok", "facebook"] }, "policy": { ... safety constraints ... }, "creative": { ... format hints, image prompts ... } }

Why this module's design matters

The brief.v1 schema is the spine. Everything brand produces gets normalized into one artifact. Forecast and studio don't need to understand brand internals — they just read the JSON. That's how brand can be 112 files of complexity without poisoning the rest of the suite.

The autonomous loop is more than a cron. It maintains a decision log, learning metrics, and policy gates. When it runs, you can audit every choice it made. Most "AI agent" systems pretend autonomy by hiding state; this one persists it.

Subagents over a monolith. Market analysis and threat scanning live as separate agents with a base class. You can add a third (e.g., a "compliance" agent) by subclassing — no rewrite needed.

How to read the size: 112 files sounds like sprawl, but most are small (CLI commands, schema definitions, store accessors). The actual logic is concentrated in plan/stages/, agents/, and loop.py. The rest is plumbing for a CLI-first interface — which is exactly what makes the suite scriptable.
